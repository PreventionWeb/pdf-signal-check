# Naming direction: UN first, useful everywhere

Naming decision recorded October 6, 2026. The user selected **PDF Signal Check** as the product name. The current local repository/package slug is `pdf-signal-check`, renamed at the user’s subsequent request; `pdfs-for-ai-actionability` is the former slug. **PDFs for AI Actionability** is retained as the original project title in its history. **PDF Input Check** was the earlier interface label. The prior evaluated shortlist below is historical, not an open naming decision.

## Adopted direction

**PDF Signal Check**

Descriptor: **Text, structure, and metadata for machine use.**

Tagline: **Inspect the PDF. Understand the input.**

“Signal” connects the name to the information software recovers from a PDF: its title, authors, text, structural relationships, and reading-order evidence. The tool checks these signals against a defined profile and recovered publication evidence, exposing conflicts and uncertainty for review. “Check” communicates an examination rather than certification. Keeping PDF explicit makes a shared link or exported report understandable, while the machine-use descriptor distinguishes this from a signing tool or a general human-accessibility audit.

The identity fits UN-system publication workflows without claiming UN affiliation, and applies to reports, repositories, and ingestion workflows in any industry. It avoids making AI the permanent brand identity: traditional checks are useful independently of an optional model. “Signal” is a metaphor rather than a claim that the checker knows every input a downstream system will use; explanations must keep the bounded extraction and advisory limits visible.

The earlier aspirational positioning option **See what machines receive** is not the adopted public tagline. This checker exposes its own bounded extraction and markup evidence, not the exact input every downstream parser or AI system will receive. The adopted tagline invites inspection without promising downstream equivalence.

First-contact copy:

> **PDF Signal Check**
>
> Inspect the PDF. Understand the input.
>
> Review extracted text, structure, and publication metadata before a PDF enters an AI or document-processing workflow. Your PDF is processed in your browser.

Limited exact-name searches for “PDF Signal Check” and “PDF Signal Check” software/tool on October 6, 2026 did not surface an obvious product using that complete name. There is an adjacent name, **PDF Signal**, on a PDF-signing site's own page. Retain the full **PDF Signal Check** identity and clear descriptor rather than shortening it to PDF Signal. This is an observed naming-conflict signal, not a conclusion about legal availability. [Observed PDF Signal signing tool](https://signature.pdfconverted.com/).

## Audience and positioning

For the initial UN-system audience, make the relationship between the publication and its machine-readable representation the central story. The Dag Hammarskjöld Library describes bibliographic metadata as a way to make documents findable and usable, including by title, author, subject, and document symbol. Its digitization workflow separately includes metadata creation and quality review. These are useful audience signals; this tool does **not** currently validate external library catalogue records, document symbols, translation equivalence, or institutional publication policy. [UN metadata context](https://www.un.org/en/delegate/un-digital-library-reaches-1-million-metadata-milestone), [Library workflow](https://www.un.org/en/library/what-we-do).

Make examples and explanations relevant to reports, policy papers, translated publications, and institutional repositories. Keep the product identity independent of any institution. Do not put UN, an agency acronym, the UN emblem, an SDG mark, or certification language in the name or visual identity without authorization. The UN system is the first intended audience, not a claimed affiliation or endorsement.

The UN's own website multilingualism standards recommend planning language support from the outset, discourage acronym-based banners and logos, and call attention to RTL layout and differing text lengths. Treat these as useful design guidance for this audience, rather than asserting that this independent tool is a UN website or meets those standards. Use a separate symbol and text wordmark; translate the descriptor and explanatory copy. English names below still need native-speaker testing in Arabic, Chinese, French, Russian, and Spanish; none has been linguistically validated. [UN multilingual web standards](https://www.un.org/en/multilingualism-web-standards).

## Directions screened out

**PageProof** is an established creative proofing product with PDF review; **PageSignal** is already used for website-change monitoring and other web products; **Folio Trace** is an existing book/paper restoration app; **Concord** is an established contract/document product. Their underlying ideas—proof, signal, trace, agreement—are relevant, but these actual identities create unnecessary confusion. [PageProof](https://pageproof.com/), [PageSignal](https://www.pagesignal.com/), [Folio Trace](https://apps.apple.com/pl/app/folio-trace/id6810162750), [Concord](https://help.concord.app/documents-contracts).

## Keep product, result, and profile distinct

- **Product name:** PDF Signal Check.
- **Product descriptor:** Text, structure, and metadata for machine use.
- **Result artifact:** PDF Signal Check report, an input-analysis receipt containing findings and captured evidence. Download filenames use the `-pdf-signal-check` suffix.
- **Acceptance label:** Text actionability profile 0.3: Yes/No, with limitations and reasons. A product name must not become the name of an external standard.
- **AI feature:** Optional local semantic screening. Name the selected model and its actual language limits in the workflow; avoid implying all checks or every language use AI.

Retain credits to Ken Hawkins's PDF-A-go-actionable and pdf-a-go-go. A new name changes neither authorship nor reference-project attribution. The original guidance was to preserve the repository slug until a separate migration was requested. That migration is now complete: the folder/package use `pdf-signal-check`, with the former slug and original project name preserved as searchable history. The private GitHub repository is [PreventionWeb/pdf-signal-check](https://github.com/PreventionWeb/pdf-signal-check); the baseline and implementation branches have been pushed. GitHub Pages has not been deployed.

## Comprehension and language validation

Show **PDF Signal Check** with its descriptor to a small mix of publication staff, librarians, and AI/data staff. Ask what they expect the tool to do, whether it repairs or signs the PDF, whether a pass certifies accuracy/accessibility, and whether it sends files to an AI service. Misunderstanding about signing, repairs, certification, or uploads matters more than name preference. Test pronunciation and meaning with native speakers before assuming cross-language suitability; this is validation of the adopted presentation, not a prerequisite to local implementation.

The product-name decision authorizes the coordinated local rebrand. This brief itself changes no source code and does not authorize publication, domain purchase, or trademark filing. The limited searches above record observed naming conflicts only; legal availability remains unassessed.
