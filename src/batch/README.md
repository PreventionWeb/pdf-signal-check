# Foreground sequential queue core

`createSequentialQueue({analyze, screen, hash, reportStore, onEvent})` is DOM-free. Services receive an original File handle (analysis/hash) or completed structural report (screen), with `{signal, configuration, onProgress}`. They must honor AbortSignal by stopping their active worker/read; the scheduler waits for settlement and never starts a second service while the old one is running. Screening must use the selected frozen configuration, declare skips explicitly, and never substitute a model. Model initialization errors need `stage: 'model-init'` or `code: 'MODEL_INIT_FAILED'`; other screening errors remain isolated to that document.

`enqueue(files)` returns stable session IDs, independent of filename. UI retains its own ID→File map for opening completed results. `start(configuration)` freezes a copied queue configuration; `pause()` finishes the current file, `resume()` schedules pending work, `cancelActive()` aborts only the active attempt, and `stopAll()` pauses and aborts. `retry(id)` replaces that item's old outcome and clears stale run state. `skip(id)` releases retained details but keeps any compact summary. `remove(id)` deliberately removes a nonactive item and handle. `reorder(ids)` requires every queued ID exactly once. `getReport(id)` returns a clone of retained detail, so presentation/export edits cannot invalidate the store estimate; `snapshot()` contains compact state, no File objects.

Admission defaults: twenty files, 300 MB total source bytes, 50 MB per file; the analysis engine separately enforces 200 pages. This is not a RAM estimate or device certification. ReportStore estimates UTF-8 JSON bytes with a 20 MB default. **One completed pending report may spill beyond that budget**: pressure pauses scheduling before any detail is silently dropped. Snapshot exposes the pending serialized size. Source handles, pending report, model/runtime heaps and parsed-document memory are not represented by that serialized budget.

Resolve pressure by explicitly `releaseDetails(ids,{consent:true})` (summaries retained), then `retainPending()` and `resume()`, or `summarizePending({consent:true})`. An individually oversized report can only be summarized or removed after an explicit choice. The injected `dispose()` hook is awaited by async `destroy()` and must terminate all adapter workers/encoders. Nothing persists to localStorage, IndexedDB or a server. Closing/reloading the tab loses queue state. Background scheduling/sleep is not guaranteed.

`model-initialization-failed` pauses after retaining that item's structural result and includes retry/structural-only action choices. `resolveModelFailure({action:'retry'})` restarts the failed item's attempt; `action:'structural-only'` continues pending files without additional AI requests. Ordinary per-document screening failures do not pause the queue. Observer callback failures are captured in `observerError` and cannot wedge the scheduler. Actual model identity is separate from requested configuration; errors/cancellation never rewrite profile acceptance.

`getPendingReport(id)` gives a clone of an awaiting-budget report for review/export; it remains unadmitted and the clone adds transient allocation outside the budget. Inject `getConditions()` to record visible/hidden/session changes at each item's measured start/end. Timings are same-context monotonic elapsed plus ISO wall times, never ETA. Retry/remove/skip of the unresolved model-failure item is guarded until its explicit action choice. Runtime worker errors preserve the initialization stage/code even if the underlying library threw a primitive.
